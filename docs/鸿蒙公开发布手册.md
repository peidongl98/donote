# DoNote 鸿蒙公开发布手册（个人开发者 · 零费用）

适用：以个人开发者身份，把 DoNote 通过 AppGallery Connect 公开测试分发出去，不上架正式市场也能按版本更新。

## 0. 费用与时间

| 环节 | 费用 | 耗时 |
|---|---|---|
| 华为开发者账号 + 个人实名 | 0 | 1–3 工作日 |
| 软件著作权登记（中国版权保护中心） | 0（2017 年起停征官费） | 30–60 工作日 |
| APP 备案 | 0 | 1–20 工作日 |
| 发布证书 / 发布 Profile | 0 | 当天 |
| .app 打包 | 0 | 10 分钟 |
| 公开测试审核 | 0 | 1–3 工作日 |

唯一可能产生费用的地方：若备案页面要求「接入服务码」，需要一台中国大陆云服务器（最低配一年几十元）。纯单机应用先在 AGC 的备案入口确认是否强制要求，不要提前买。

## 1. 必须逐字一致的三处信息

| 项 | 值 |
|---|---|
| 应用名称 | DoNote |
| bundleName | com.peidongl98.donote |
| 签名算法 | SHA384withECDSA |

应用名称、包名在 AGC 应用、备案信息、打包产物三处必须完全一致，大小写敏感，改一个字就签不过或备案核验失败。

## 2. 开发者账号与实名

1. 打开 developer.huawei.com，注册账号。
2. 进入「个人中心 → 实名认证」，选个人，上传身份证正反面，做人脸核验。
3. 通过后在同一账号下进入 AppGallery Connect。

## 3. 软件著作权（可与备案并行）

1. 打开 ccopyright.com.cn（中国版权保护中心），注册个人账号。
2. 选择「软件著作权登记 → 计算机软件著作权登记」，不选加急。
3. 需要上传：
   - 源码：前 30 页 + 后 30 页，每页 50 行，删空行，页眉写软件名称与版本号。
   - 说明书：功能截图 + 操作说明，5–15 页。
   - 身份证正反面。
4. 提交后等受理与审查，全程 0 元，不要买任何「加急包」。
5. 公测提交时若证书还没下来：AGC 在版权信息处提供《免责函》模板，下载签字后上传即可先过审，后续补证。

## 4. APP 备案

1. 在 AGC 里进入该应用，找「APP 备案」入口（应用信息或版本信息页有指引链接），按页面走；也可以直接在工信部政务服务平台 gz.miit.gov.cn 提交。
2. 填写内容：
   - 主办者：本人姓名、身份证号、手机号、常住地址（精确到门牌）。
   - 应用信息：名称 DoNote、包名 com.peidongl98.donote、版本号、应用分类（工具类）、功能简介 300–500 字，只写实际有的功能，不写「智能」「AI 增强」这类没有实现的描述。
   - 图标与截图：1024×1024 图标，3–5 张真实界面截图。
3. 签名 MD5 从这里取（备案表可能要求）：

   ```
   keytool -list -v -keystore apps/harmony/sign/donote.p12 -alias donote
   ```

   口令在 apps/harmony/sign/.storepass 里。输出里找 MD5 与 SHA256 两条指纹。
4. 无自有服务器时：备案表里「服务器 / 域名」如实填「无，应用为本地单机运行」；若系统强制要接入服务码，再按第 0 节处理。
5. 审核通过后拿到备案号，形如「粤ICP备xxxxxxxx号-xA」。
6. 备案号必须展示在应用内（设置或关于页），且与包名绑定，不能只写在商店页面。

## 5. 发布证书与发布 Profile

1. DevEco Studio → Build → Generate Key and CSR。已有 `sign/donote.p12`，点 Skip 复用，只生成新的 `.csr`。
2. AGC → 证书、APP ID 和 Profile → 证书 → 新增证书 → 类型选「发布证书」→ 上传 `.csr` → 下载 `.cer`。
3. AGC → Profile → 新增 → 类型选「发布」→ 绑定 com.peidongl98.donote 与刚下载的发布证书 → 下载 `.p7b`。
   发布 Profile 的设备列表为空是正常的，它不绑 UDID。
4. 把 `.p12`、`.cer`、`.p7b` 放进 `apps/harmony/sign/`，按 `sign/README.md` 的模板填 `build-profile.json5`：

   ```json5
   "signingConfigs": [
     {
       "name": "default",
       "type": "HarmonyOS",
       "material": {
         "storeFile": "sign/donote.p12",
         "storePassword": "<.storepass 里的值>",
         "keyAlias": "donote",
         "keyPassword": "<同 storePassword>",
         "certpath": "sign/donote.cer",
         "profile": "sign/donote.p7b",
         "signAlg": "SHA384withECDSA"
       }
     }
   ]
   ```

   并在 `products[0]` 加一行 `"signingConfig": "default"`。

## 6. 打包 .app

1. 先把前端产物同步进 `apps/harmony/entry/src/main/resources/rawfile/www`（用 `apps/web/dist`）。
2. 改 `AppScope/app.json5` 的 `versionCode` 与 `versionName`，每次提交必须递增。
3. Build → Build Hap(s)/APP(s) → **Build APP(s)**，产物在 `build/outputs/app/release/`，扩展名 `.app`。
4. 校验：解压 `.app`，看 `pack.info` 里的 bundleName、versionCode 是否与预期一致。

## 7. 提交公开测试

前置：AGC 已创建该应用、备案号已下、`.app` 已用发布证书签名。

1. AGC → 我的应用 → DoNote → 左侧「测试」→「公开测试」→ 创建测试版本。
2. 上传 `.app`，核对解析出的包名与版本号。
3. 填应用信息：
   - 图标、3–5 张截图、一句话简介、详细描述、分类。
   - 隐私政策链接，必须 HTTPS 且可直接打开。DoNote 目前没有这个页面，需要先做一份并部署，见第 9 节。
   - 备案号、开发者联系方式。
4. 配置测试发布：
   - 下载安装人数上限，按需填。
   - 发布方式：可只勾「生成分享链接」，不必挂到「应用尝鲜」专区。
   - 测试起止时间。
5. 提交审核，1–3 个工作日。通过后拿到分享链接，任何人打开即可安装。
6. 被驳回按意见改，重新提交。

## 8. 迭代更新

每次更新只重复第 6、7 步：改版本号、重新打 `.app`、新建一个测试版本提交。证书与 Profile 不变。
用户在原来的分享链接或应用市场里更新，不需要重新拉人。

## 9. 待补项（现在缺的东西）

1. **隐私政策页**：公测必填。当前 `https://donote.pages.dev/privacy` 是 404，源码里也没有。需要写一页，部署到同一域名，内容至少覆盖：收集哪些数据（DoNote 是本地存储，WebDAV 凭据存本机钥匙串）、是否上传服务器、第三方 SDK、用户如何删除数据、联系方式。
2. **应用内备案号展示**：拿到备案号后加在设置或关于页。
3. **AGC 应用**：确认 com.peidongl98.donote 已在 AGC 创建，否则证书和 Profile 申请不了。

## 10. 常见驳回原因

- 应用名称或包名与备案信息不一致。
- 隐私政策链接打不开，或内容与实际行为不符（例如声明不联网但实际请求 WebDAV）。
- 截图带其他应用市场水印。
- 首次启动没有隐私弹窗，或默认勾选同意。
- 功能描述夸大，写了未实现的能力。
