## 一、一句话现状

Windows 客户端已上线可用（`https://donote.pages.dev` 下载）。数据存在用户自己的 WebDAV 网盘（默认坚果云，也可填 Nextcloud / 群晖 / 自建），DoNote 没有服务端。已实现的功能全部通过真实服务器验收（47/47，无 mock）。

## 三、数据层能力（已实现）

- 连接 / 断开（凭据存进 Windows 凭据管理器，不落盘、不进仓库）
- 笔记：新建、编辑（自动保存 + 并发写排队）、读取、删除
- 标题即文件名：改标题连带重命名文件，重名自动补后缀
- 搜索：标题 + 正文，匹配后补出摘要
- 文件夹：新建、重命名、删除
- 删除进 `.trash/`，记下原路径与删除时间；可恢复回原位置，或彻底删除
- 连不上 / 凭据错 / 被拒时给出具体原因

## 五、重新设计前必须知道的边界

这几条会实际约束界面能做到什么，建议先过一遍再动手。

1. **没有服务端**，所以界面上不能出现：托管式分享链接、协作、评论、消息推送、服务端搜索。也不能出现 DoNote 自己的账号 / 注册 / 会员 / 额度 —— 空间和流量都是用户自己网盘的。
   ⚠️ 但**分享本身要做**，方式是导出成自包含 HTML 文件，不需要服务端。
2. **每一次操作都是一次网络往返**。列表来自客户端遍历目录，笔记变多后会变慢。界面设计要按「请求数」衡量交互成本。
3. **服务器限流**（以坚果云免费版为例）：每 30 分钟 ≤ 600 次请求、单目录 ≤ 750 项、单文件 ≤ 500MB、每月上传 1GB / 下载 3GB。批量操作、自动刷新、实时预览这类设计要受它约束。
4. **只有原生壳能连 WebDAV**（服务端普遍不返回跨域响应头），所以不存在「打开网页就能用」的版本。
5. **一篇笔记 = 一个 `.md` 文件**，文件夹 = 真实目录。附件与图片目前没有实现。
6. **多设备同时改同一篇没有冲突处理**，现在以后写入者为准。

## 七、下一阶段需求与计划

2026-10-10 订。目标是让 DoNote 变成「打开就是排版好的笔记」，而不是让人自己敲 Markdown 语法。

### 需求清单

| # | 需求 | 说明 |
|---|---|---|
| 1 | 主编辑区所见即所得 | 打开笔记看到的就是排版后的样子，正文里不出现 `#`、`**` 这类符号 |
| 2 | Word 式工具栏 | 段落样式（标题层级 / 正文）、加粗、斜体、删除线、行内代码、有序与无序列表、任务清单、引用、代码块、表格（可视化增删行列）、链接、图片、分割线、思维导图 |
| 3 | 笔记嵌套 | Notion 式：一条笔记下面挂子笔记，点进去进入下一层 |
| 4 | 导入 | 单个或多个 `.md` 文件；整个文件夹（连目录结构一起建好） |
| 5 | 导出 HTML 分享 | 导出自包含单文件 `.html`，样式内联、图片内嵌，双击可看、可直接发出 |
| 6 | 每个功能配帮助文档 | 写一个功能就配一份对应的应用内帮助页（形式同坚果云连接引导） |

### 笔记嵌套的文件系统映射

Windows 不允许同一目录下同名文件与文件夹共存，因此父笔记正文放进目录内：

```
框架笔记/
  index.md      ← 这条笔记自己的正文
  子笔记 A.md
  子笔记 B/
    index.md
    …
```

**副作用**：文件夹与笔记合并为同一个概念 —— 一个目录就是一个页面，既能写正文也能装子笔记；没有 `index.md` 的目录即纯文件夹。

### 执行顺序

| 批次 | 内容 | 为什么排这个位置 |
|---|---|---|
| 1 | 所见即所得编辑器 + Word 工具栏 | 核心体验，技术不确定性最高，先验证 |
| 2 | 导出 HTML 分享 | 独立功能，不依赖编辑器改造，可随时插入 |
| 3 | 笔记嵌套 | 要动数据模型，须排在编辑器稳定之后 |
| 4 | 导入、思维导图 | 依赖前三批铺好的基础 |

### 待确认

- 思维导图：暂定用 Mermaid `mindmap` 块（工具栏一键插入、可视化编辑，文件仍是干净 md，导出 HTML 也能渲染）
- 导入：暂定支持单 / 多个 `.md` 与整目录导入
