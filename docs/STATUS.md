## 三、数据层能力（已实现）

- 连接 / 断开（凭据存进 Windows 凭据管理器，不落盘、不进仓库）
- 笔记：新建、编辑（自动保存 + 并发写排队）、读取、删除
- 标题即文件名：改标题连带重命名文件，重名自动补后缀
- 搜索：标题 + 正文，匹配后补出摘要
- 文件夹：新建、重命名、删除
- 删除进 `.trash/`，记下原路径与删除时间；可恢复回原位置，或彻底删除
- 连不上 / 凭据错 / 被拒时给出具体原因

## 五、重新设计前必须知道的边界

这几条会实际约束界面能做到什么，建议先过一遍再动手。

1. **没有服务端**，所以界面上不能出现：分享链接、协作、评论、消息推送、服务端搜索。也不能出现 DoNote 自己的账号 / 注册 / 会员 / 额度 —— 空间和流量都是用户自己坚果云的。
2. **每一次操作都是一次网络往返**。列表来自客户端遍历目录，笔记变多后会变慢。界面设计要按「请求数」衡量交互成本。
3. **坚果云免费版限流**：每 30 分钟 ≤ 600 次请求、单目录 ≤ 750 项、单文件 ≤ 500MB、每月上传 1GB / 下载 3GB。批量操作、自动刷新、实时预览这类设计要受它约束。
4. **只有原生壳能连坚果云**（服务端不返回跨域响应头），所以不存在「打开网页就能用」的版本。
5. **一篇笔记 = 一个 `.md` 文件**，文件夹 = 真实目录。附件与图片目前没有实现。
6. **多设备同时改同一篇没有冲突处理**，现在以后写入者为准。

## 七、技术路线（已定，不再改）

- 前端：Vite 8 + Vue 3.5 + vue-router + Pinia，`apps/web`
- 桌面壳：Tauri 2，`apps/desktop`。Rust 侧 reqwest 发请求绕开跨域，凭据进系统凭据管理器
- 存储：用户自己的坚果云 WebDAV
- 分发：Cloudflare Pages 承载下载页 + 安装包 + 更新清单；更新用 minisign 签名，私钥在 `.updater-key/`（**丢失后无法再发版**）
- 仓库：`peidongl98/donote`（私有），当前 `main` = `de2e298`

已废弃、不要重新引入：Cloudflare Worker / D1 / 腾讯云短信 / 分享功能 / PWA 的后端接口。
