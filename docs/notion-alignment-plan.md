# 对齐 Notion：页面块 / 正文主体 / 字号

> 依据：Notion 官方帮助文档（Links & backlinks、Math equations）＋ 对 DoNote 现有实现的读码。
> 方向已定：**完全对齐 Notion**（C 选甲）；**正文区要够大、有沉浸感**。
> 定案（2026-10-16）：字号控件＝**± 两个按钮、不显示数字**；**公式不动**；
> **A 恢复执行**（此前「待定」是术语误会，用户说的「名字」是**本篇标题**，不是 `[[名字]]`，见 §A）；
> **新增 E 建议标签**（自动提取关键词，虚线显示、点一下才采纳、不落盘）。
>
> 实施进度（2026-10-16 收）：**A / B / C / E 四项已全部落地并各自实测通过**，D 不做。
> 未发版 —— 用户要求先停在发版前，等他告知本版本要一并修的问题。
> 实测脚本：`.workbuddy/tmp/c-verify.cjs`（22 项）、`.workbuddy/tmp/e-verify.cjs`（15 项）、
> B 的量化数据见 §B 各小节。

## 一、Notion 的模型（核实过的三条事实）

1. **`[[` / `@` 是行内链接，不建立层级。**
   官方原话：「@提及某个页面会更类似于超链接。你@提及的页面不会显示为被提及所在页面的子页面。」
2. **`/link`、`/page` 是正文里的一行块，建立层级。**
   官方原话：「当你新增『链接到页面』区块时，该链接页面会显示在侧边栏中您插入链接的页面下方，就像其他下层页面一样。」
3. **反向链接自动生成，位置在页面顶部，鼠标移上去才出现。**
   官方原话：「反向链接会自动出现在页面标题上方，当页面有时悬停显示。」

**结论**：Notion 里**没有**「正文之外自动列出子页面」这块界面。子页面就是你在正文里插的那一行块。
层级来自**正文里插了什么**，不来自文件夹。

## 二、DoNote 现状与差距

| 概念 | 落盘的内容 | 显示在哪 | 差在哪 |
|---|---|---|---|
| `[[名字]]` | 纯文本 + 染色（蓝 = 存在，红 = 还没建） | 正文里 | 位置对，形态缺「块」这一档 |
| 「子页面」 | 读**磁盘目录里的直系条目**（含纯文件夹、普通笔记） | 正文下方独立区，卡片列表 | Notion 没有这块界面 |
| 「被以下笔记提到」 | 谁写了 `[[这篇标题]]` | 正文下方独立区，卡片列表 | Notion 在页面顶部，且是一行轻条 |

根源：**DoNote 的层级是磁盘目录，Notion 的层级是正文里的块。**
现在那个「子页面」列表读的是目录里的直系条目 —— 跟 Notion 的子页面只是名字撞了。

正文区的「小」来自另一组数字（`apps/web/src/components/editor/NoteEditor.vue`）：

| 项 | 现在 | 问题 |
|---|---|---|
| 正文外壳 | `background: var(--surface)` ＋ 边框 ＋ 圆角 ＋ `padding: 24px 32px` | 正文是一张**卡片**，有可见边界，不像「页面」 |
| 滚动 | 正文自己 `overflow-y: auto` | 滚动条落在卡片内部，不是窗口右缘 |
| 字号 | 硬写 `15px` | 偏小；且没用 `--fs-base` 令牌；不可调 |
| 正文下方 | 还压着两个卡片区块 | 与正文争纵向空间 |
| 内容列 | 全站共用 `clamp(900px, 68vw, 1400px)` | 编辑页是全站唯一没接入 `.page-body` 骨架的页面 |

### 全屏留白（量化）

显示器 1920×1080。全屏、侧栏展开 → 编辑区可用 **1660px**。

| | 内容列 | 两侧留白 | 正文可用 |
|---|---|---|---|
| 现在（`68vw`） | 1306 | 各 177（合计 21%） | 1258 |
| 改后（`88vw`，上限 1600） | 1600 | 各 30（合计 3.6%） | 1552 |

窗口化 1120 时（可用 860）两版**完全一致**：正文 812px，两侧无留白 —— 改动只作用于宽屏。

## 三、改动

### A. 正文内页面块 —— ✅ 已实施

> **状态修正（2026-10-16）**：此前记的「待定」是一场术语误会。用户说「这个名字的渲染看齐 notion 不太好」
> 里指的**不是** `[[名字]]` 的链接文字，而是**本篇笔记自己的标题**；他真正担心的是
> 「**标题会被滚走**」——那是当时计划里的 **B1**（把滚动从正文挪到整页）带来的副作用，不是 A 的问题。
> B1 因此**作废**（见 §B1），A 恢复执行。已实现并通过 12 项实测（`.workbuddy/tmp/a-shots.cjs`）。

**判据**：一个段落**去掉首尾空白后整段只有 `[[名字]]`**。

- 命中 → 渲染成页面块：左侧页面图标 ＋ 标题，通栏一行，鼠标移上去出底色，点击进入
- 不命中（`[[名字]]` 混在句子里，如「相关：`[[A]]`」）→ 保持现在的行内链接形态，不变

**落盘一个字节都不改**。仍然是 `[[名字]]` 原文 —— 只改渲染分支，**不新增节点类型、不碰数据层**。
用的是现在这套机制（`wikilink.ts` 的 `Decoration`）：段落级命中时改用 `Decoration.node` 给整个段落挂 class，
图标由 `::before` 出。`handleClickOn` 的点击逻辑照旧复用。

**取舍**（要你知道）：按「独占一段」判定，意味着**没法在单独一行放一个行内链接**。
换来的好处是落盘完全不变、Markdown 里独占一行本来就是块级的惯例。
（另一条路是加 `![[名字]]` 之类的嵌入语法来显式区分，那就要动落盘格式，不做。）

**顺带**：`[[` 补全菜单里选中后，如果当前段落只有这一项，提示会变成块。

### B. 正文区成为页面的主体

#### B1 外壳：去掉卡片，滚动不动

⚠️ **2026-10-16 修正**：原计划是让编辑页接入 `.page-body` 骨架、把滚动挪到内容区整块。**这个计划作废** ——
它会让**标题输入框和标签条跟着滚**，而用户明确要「名字不跟着滑动，这样我能知道自己在哪篇」。
（顶栏面包屑本来就在滚动容器外，不受影响；但标题与标签条在内容区里。）

所以：**滚动保持现状**（留在 `.donote-surface` 内）。标题与标签条本来就在 `.donote-surface` 之外 →
天然不滚，不用动；`onSurfaceScroll`（`NoteEditor.vue:171`，滚动时收起浮动工具栏）也不必改，滚动容器没变。

代价：滚动条仍在正文区右缘，不是窗口最右缘。取舍标准是「保标题固定」优先。

具体只改样式：
- `.donote-surface` 去掉卡片外观 —— `background` / `border` / `border-radius` / `padding: 24px 32px`
- **保留** `overflow-y: auto` 与 `min-height: 46vh`（正文短时点下方空白仍能落光标）

#### B2 全屏留白

编辑页局部覆盖 `--content-max`（CSS 变量作用域覆盖，**列表页 / 设置页不受影响**）：

```css
.editor { --content-max: clamp(900px, 88vw, 1600px); }
```

效果见上表。这个值一个变量就能调：全屏读长段落若觉得行太长，把上限降到 1440 附近即可。

#### B3 字号可调

**关键事实**：标题本来就是相对单位。`editor.css` 里 `h1 = 1.7em`、`h2 = 1.4em`、`h3 = 1.18em`、
行内代码 `0.88em`，全部挂在 `.ProseMirror` 那**唯一一处** `font-size: 15px` 上。
所以「调一个字号、所有标题随之等比放大」天然成立，**不用动任何标题规则**，
也**碰不到 md 内容**（纯 CSS，落盘无关）。

形态（已定）：**± 两个按钮，不显示数字**

- 位置：工具栏最前方（`EditorToolbar.vue` 的第一行，段落样式下拉之前）
- 档位制：14 / 15 / 16 / 17 / 18（每按一下变化明显，比 1px 连续步进好用）
- 到端点按钮置灰，不是「按了没反应」
- `Ctrl+0` 回标准 15px —— 「用户不需要知道字号」的代价是必须有回头路
- 存在 `localStorage`：全局偏好，不随笔记走、不落盘、不跨设备同步 —— 这才叫「全文基础字号」
- 数字不上界面；`aria-label`（增大字号 / 减小字号）与悬停 tooltip 承载
- 快捷键 `Ctrl+−` / `Ctrl+=`，**只在正文有焦点时拦** —— 侧栏、列表页仍是浏览器缩放
  （网页端 Ctrl+± 默认是浏览器缩放，拦下来就没了，所以只在编辑器内接管）

### C. 正文外的两块按 Notion 挪走 —— ✅ 已实施

> **依赖关系（2026-10-16 修正）**：此前记的「A 待定 → 删子页面区跟着搁置」已随 A 恢复执行而解除（术语误会，见 §A）。
> 用户同时拍板：**层级看侧栏树就够**，正文外不再重复列一份。
> 「子页面」列表读的是**磁盘目录的直系条目**，与 A 的正文页面块不是同一份数据 ——
> 但两者并不冲突：A 管「正文里写了链接的」，侧栏树管「磁盘上的目录层级」，各司其职。

- **「子页面」区已删除（实测 .children / .child-card / 「子页面」字样均为 0）。**
  层级看侧栏树就够（Notion 也是靠侧栏看层级）。
  「新建子页面」按钮移进顶栏 `⋯` 菜单，且是**首项**（实测通过）。
- **「被以下笔记提到」上移到正文顶部**，做成一行「N 篇提到这里 ▾」，默认收起，点开才列出。
  没有反链时这一行不渲染（Notion 也是没有就不显示）。
- **纯文件夹不再在详情页出现** —— 它只在侧栏树里。这也顺带解决现在「子页面列表里混着文件夹」的问题。

### D. 块级公式 —— 不做

结论：**不单独放大、不加按钮**，只跟着基础字号走。三条理由：

1. **「它的漂浮工具栏」不存在。** `FloatingToolbar.vue` 只在**选中文字**时出现，里面只有
   加粗 / 斜体 / 删除线 / 行内代码 / 清除格式五个行内操作；块级公式是 atom 节点，点它弹的是 `MathPanel`。
   要加按钮等于新建一套浮层。
2. **单个公式的尺寸要记住就必须落盘**（否则刷新即丢），而落盘要往 `.md` 里塞尺寸 —— 触「不改数据模型」红线。
3. **它现在「小」是外壳造成的**：卡片底 ＋ 边 ＋ 12px 内边距，字号又跟正文一样
   （KaTeX 的 display 模式本身不放大字号，是我们没给）。外壳一改它自然变大。

若改完仍嫌块级公式小，给它单独一档 `1.15em` 即可 —— 纯 CSS，不用按钮、不用落盘。

### E. 建议标签（自动关键词）

**已定形态**：标签条旁显示一行**虚线框的建议标签**，**点一下才写成正式标签**，不自动落盘。

理由（都是实测过的）：

1. **落盘会写进 frontmatter 的 `tags`** —— 手动删掉后下次又被加回来，冲突无解；
   且侧栏标签聚合（`notesApi.tags()` 遍历**全部笔记**统计）会被自动词淹没，标签云变成噪音。
2. 自动标签**随内容变化而变**，而标签的价值在「稳定 ＋ 用户意志」。所以它只能是建议，不能是事实。
3. 不落盘 → 零冲突、零意外写入、不污染标签云，且**完全不碰数据层**。

**提取方式**：`Intl.Segmenter`（浏览器**原生**，零依赖）分词 → 过滤（停用词 / 单字 / 符号）→ 词频 top 5。

实测（5600 字符的 md，耗时 **22ms**）：`正文(19) 字号(16) 滚动(11) Notion(10) 按钮(9)` —— 可用。
停用词表要补（实测漏出「不要」「必须」这类），几十行硬编码。

**不做**「取文内标题」那条路：出来的东西是**句子**（带「一、」编号、带 markdown 残留），不像标签。

**刷新时机**：跟着已有的「正文变化 → 保存」算一次，不新增第三层防抖
（编辑器已有序列化 200ms ＋ 保存 1200ms 两段）。

**范围**：只算**当前打开的这篇**（内容在内存里）。全库算要读所有笔记正文并逐篇分词 ——
列表页会变慢、标签云会爆。

## 四、落盘红线

A / B / C / E **全部不改数据模型**。`[[名字]]`、`$$…$$`、`$…$` 原文照旧，`.md` 文件里一个字节不变。
C 里的删除是**界面删除**，不动磁盘上的任何笔记或文件夹。
字号是纯 CSS ＋ `localStorage`，与落盘无关。
E 的建议标签**默认不写文件**；只有用户点一下采纳，才走既有的 `notesApi.update(id, { tags })`
（读回原文件 → 用同一份 body 重新序列化，**正文一字节不动**）。

## 六、回归影响

涉及套件：`stage2`（编辑器 / 源码模式字节精确）、`stage4`（工具栏）、`stage5`、
`stage6`（源码模式）、`nested`（嵌套 / 导航）、`math`（公式）。

需要新增或调整的断言：
- `nested`：「子页面」区相关的断言改成侧栏树 / 顶栏菜单路径
- `math`：块级公式**不再**需要字号/背景断言（本次不动它）；保留原有落盘断言
- 新增：独占一段 `[[名字]]` → 页面块；混在句中 → 行内链接
- 新增：字号档位 —— 按 `A+` 后 `h1` 的计算字号同比变大（只断言正文会假绿）
- `stage4`：工具栏按钮数变化（多两个字号按钮）
- `stage2` / `stage6`：`.donote-surface` 的 class 名保留，选择器不受影响；
  **滚动容器也没变**（B1 作废，滚动仍留在 `.donote-surface` 内）→ 这两套**不需要改**
- 新增：建议标签 —— 提取结果非空；点一下后 `tags` 多一项且 frontmatter 被写；
  **不点则 md 逐字节不变**（这条必须有，否则「不落盘」的承诺没有断言）
