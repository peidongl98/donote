## 〇、方法与证据

**「DoNote 行为」一列全部是本机实测，不是读代码推断。** 用仓库里的 mock 假 DAV（零坚果云额度）驱动真实
dev server，逐个点击工具栏、并把结果读到「落盘 Markdown」为准。探针脚本在
`.workbuddy/tmp/donote/audit-editor{,2,3,4}.cjs`（不入库）。

**「Notion 行为」一列按 Notion 桌面端 / 网页版的既有交互填写。本次没有真的打开 Notion 逐项对点**，
这一列是参照系，不是实测；如果你认为某一条与你的 Notion 印象不符，以你的为准。

关键实测原始输出（摘要）：

```
[引用]     连点 3 次 → 落盘 `> > > 引用`（嵌套 3 层）
[引用取消] 点 1 次深度 1 → 再点 1 次深度 2（回不到 0）
[无序列表] 连点 3 次 → ul 总数 1、嵌套深度 1（第 2 次起点了没反应）
[有序列表] 连点 3 次 → 同上
[任务清单] 点 1 次 → <li data-item-type="task" data-checked="false">（可用）
           再点一次 → checked 被清掉，仍留在无序列表里（回不到正文）
[代码块]   点 1 次 pre=1 → 再点 1 次 pre=0（toggle 正常）
[表格]     空文档插入 → 光标落在第一个单元格，操作行出现
           有正文时插入 → 落盘顶层节点 = P,TABLE，光标仍停在前一个段落 → 操作行不出现
           手动点进单元格后：下方加行 ✅ 右侧加列 ✅ 删除本行 ✅ 删除本列 ✅ 删除表格 ✅（落盘均正确）

[占位文案]  .donote-surface::before = "用 Markdown 写点什么…"
[控制台]   全程 0 条错误
```

另外核对了 Tauri 2.12.2 自带的拖拽脚本
（`~/.cargo/registry/src/*/tauri-2.12.2/src/window/scripts/drag.js`）：它沿 `composedPath` 向上找，
**裸属性 `data-tauri-drag-region` 只认「被直接点到的那个元素」**（`return el === composedPath[0]`）。

## 一、逐项差异表

| # | 操作 | Notion 行为 | DoNote 行为 | 严重度 | 建议 |
|---|---|---|---|---|---|
| 1 | **拖动窗口**（用户报告） | 有系统标题栏，任何位置可拖 | `AppHeader.vue` 的 `data-tauri-drag-region` 是裸属性，只加在 `.topbar` / `.crumbs` / `.titles` 上；`.titles` 内部整块被 `h1.title` / `p.subtitle` 覆盖，而裸属性只认直接点击的元素 → **标题区域拖不动**（实测走查 + 读 Tauri 拖拽脚本，见 §〇） | **P0** | `.topbar` 改 `data-tauri-drag-region="deep"`，并**删掉** `.crumbs` / `.titles` 上的裸属性（裸属性会短路整条向上查找，反而让 deep 失效）。`deep` 下按钮 / 链接 / 输入框仍会自己拦住拖拽，不影响点击 |
| 2 | **点「引用」取消引用**（用户报告） | 再点一次回到正文 | `toggleBlockquote` 实为 `wrapInBlockquoteCommand` = ProseMirror `wrapIn()`，**只包不切**；连点 3 次落盘 `> > > 引用`，且没有任何取消入口 | **P0** | 自写 toggle：当前选区已在 `blockquote` 里就 `lift`（`lift` / `liftListItem` 同族），不在才 `wrapIn`。同理适用于列表 |
| 3 | **有正文时点「表格」→ 增删行列**（用户报告） | 插入后在表格内，行列控件立即可用（Notion 用悬停 + 按钮） | 插入本身正确（3×3），但光标**留在前一个段落**，`state.inTable` 为 false → `.toolbar .row.is-table` 整行不渲染 → 用户找不到任何增删入口，判定为「不能用」。手动点进单元格后 5 个按钮**全部正常且落盘正确** | **P0** | 插入表格后主动把选区放进第一个单元格（`TextSelection.near(doc.resolve(表格起始 + 2))` 之类），别依赖预设的 `Selection.findFrom` |
| 4 | **连点「无序列表」/「有序列表」** | 再点一次回到正文 | `wrapInBulletList` / `wrapInOrderedList` 也是 `wrapIn()`；已在列表里时 `findWrappingOutside` 返回 null → 命令失败 → **第 2 次起点击毫无反应**，用户以为按钮坏了，也没有取消路径 | **P1** | 与 #2 同一处修：列表也做成「在列表里就 lift 出来」 |
| 5 | **连点「表格」** | 只有一张表；再点无变化 | 每点一次就**新插一张 3×3 表**（在表内点也会再插一张） | **P1** | 已在表内时改为「定位/不动作」，或改成像 Notion 一样给尺寸网格（见 #12） |
| 6 | **连点「任务清单」** | 在「待办」与「正文」之间切换 | 第 1 次正确（`<li data-item-type="task" data-checked="false">`）；第 2 次只是把 `checked` 清掉，**仍留在无序列表里**，回不到正文段落 | **P1** | 取消时整条 `lift` 出列表，而不是只清 `checked` |
| 7 | **点「分割线」** | 插入一条线，不留多余空块 | 预设命令 `insertHrCommand` = `replaceSelectionWith(hr).insert(from, 空段落)`，**每次都在前一行插一个空段落**；空段落序列化成 `<br />` → .md 里每点一次多一个 `<br />` | **P2** | 点完分割线后把那个空段落清掉，或换成「插入后把选区放到 hr 之后的新段落且不留前导空段」 |
| 8 | **空行与 `<br />`** | 空行就是空行 | 空段落靠 `preserveEmptyLine` 写成 `<br />` 才能 round-trip（否则存一次空行就丢）。段间留一个空行 → .md 出现 `<br />` | **P2（不建议改）** | 这是**有意的保真手段**，改掉会丢空段落 → 触碰「不改数据模型」红线。建议只处理 #7 那一处来源，不关这个开关 |
| 9 | **编辑器占位文案**（用户报告） | 空笔记给「输入 / 按 '/' 唤出命令」这类引导 | 所见即所得编辑器里写 **「用 Markdown 写点什么…」**；正文根本不出现 Markdown 符号，用户会以为要手写 `#` `**`。且没有一句提示「标题即文件名」「自动保存」 | **P2** | 所见即所得下换成「直接写，格式自动成形」之类；源码模式保留原句（那句话在源码模式是对的）。一字不改也可以，但要你确认这是有意的 |
| 10 | **块级手柄（悬停 ⋮⋮）** | 悬停块左侧出现 ⋮⋮：拖动排序、删除块、复制块、转成、移到… | **完全没有**（`.ProseMirror` 内 handle/grip/drag 元素数 = 0）。块级操作只能靠顶部工具栏和「更多」面板 | **P2** | 若要做，最小版＝悬停显示 ⋮⋮ + 点击弹一个小菜单（删除块 / 复制块 / 转为）。属新功能，建议单独立项，不混进本轮修 bug |
| 11 | **撤销 / 重做** | Ctrl+Z / Ctrl+Y，顶栏也有按钮 | 快捷键**可用**（实测 AAABBB → AAA → AAABBB），但**界面里没有任何按钮**，全靠记 | **P2** | 顶栏加一对撤销/重做按钮（`history` 插件已提供 `undoCommand` / `redoCommand`） |
| 12 | **表格尺寸与对齐** | 点「表格」给 8×8 尺寸网格；单元格可设对齐 | 固定 3×3，没有尺寸选择；`setAlignCommand` / `selectRowCommand` / `selectColCommand` 命令都已在包里存在但**没接进界面** | **P2** | 一行小改动：接上对齐与「选中整行/整列」，尺寸网格可后置 |
| 13 | **工具栏快捷键提示** | tooltip 里写「Ctrl+B」等 | 快捷键实际可用（Milkdown 预设：`Mod-b` / `Mod-i` / `Mod-e` / `Mod-Alt-8` …），但 `title` 只写中文名，用户无从发现 | **P2** | `title` 补上快捷键，一行一个 |
| 14 | **代码块语言** | 代码块右上角可选语言、带高亮 | 无语言选择；只有「思维导图」按钮借 `language=mermaid` 插块。普通代码块没有语言概念 | **P2** | 可选。建议先不做（当前无高亮，加语言也看不出差别），除非你另有要求 |
| 15 | **链接** | 选中文字→粘贴/输入 URL 即成形；点链接弹原地菜单（打开/编辑/复制/移除） | 选中文字后弹层填地址（可用）；但未选中文字时会把 URL 本身当链接文字插入，且**没有点击链接的原地菜单**（编辑/移除只能在弹层里且要选中文字） | **P2** | 补「点链接 → 小菜单（打开 / 编辑 / 移除）」，并把光标落在链接内时的弹层入口补齐 |
| 16 | **空列表 / 搜索无结果等空态文案** | 有明确空态与引导 | **已做得不错**：首页「还没有笔记 / 随时记录，自动保存」、文件夹「点右上角加号，直接在这里写笔记」、回收站「删除笔记后会先进入这里，随时可以恢复」 | — | 无需改动 |
| 17 | **光标位置（点击落点）** | 点哪落哪 | 实测正常：点空白区、点单元格、方向键移动、切模式后重建，均符合预期（`prosemirror.css` / `tables.css` 已手工引入，此前的坑已修） | — | 无需改动（唯一例外是 #3 的插入后落点） |
| 18 | **代码块 toggle** | 再点回到正文 | 正常（pre 1 → 0），`toggleCodeBlock` 自写了判断 | — | 无需改动 |
| 19 | **Markdown 输入规则** | `/` 唤出命令菜单 | `> ` `- ` `***` 等输入规则**可用**（实测「> 」→ blockquote 1）；但**没有 Notion 的 `/` 命令菜单** | **P2** | `/` 菜单是 Notion 的核心发现路径。属新功能，建议单独立项 |
