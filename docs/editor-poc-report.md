| 候选 | 用例 1 外部编辑容忍 | 用例 2 打开即写 | 判定 |
|---|---|---|---|
| Milkdown 7.22.3 | ❌ 失败（6/7 文件被改写） | ✅ 通过 | **淘汰** |
| Vditor 4.0.0 · `ir`（官方推荐） | ❌ 失败（7/7 文件被改写） | ✅ 通过 | **淘汰** |
| Vditor 4.0.0 · `wysiwyg` | ❌ 失败（7/7 文件被改写） | ✅ 通过 | **淘汰** |
| Vditor 4.0.0 · `sv`（分屏源码） | ✅ 通过（6/7 文件逐字节一致） | ✅ 通过 | 通过，但**不是所见即所得** |

要点：

1. **「打开 → 什么都不改 → 保存」就会改写文件**，两个编辑器的所见即所得模式都如此。这不是边界情况，是常态。
2. **改写量与文件内容强相关**：同一个编辑器，`极端.md` 被改 71~75 行，`空文件.md` 只差 0~1 字节。
3. **两者改写的方向不同**，说明这是各自的 Markdown 序列化器（Milkdown 走 remark-stringify，Vditor 走 Lute）的既定风格，不是 bug，也几乎没有配置项可关。
4. **Vditor 的 `sv` 模式逐字节一致**，因为它的编辑区本质是一个源码 textarea + 右侧预览。它证明了「字节精确」在 Vditor 这套技术栈里做得到，但代价是放弃所见即所得。
5. **唯一的达标项**：Milkdown 对 0 字节空文件保持 0 字节（Vditor 会补一个换行）。

**因此按任务书规定，此处停下等决策**，不自行进入第二轮。

## 四、方法

测量口径按任务书原文：**记录 md5 → 打开 → 不修改 → 触发一次保存 → 关闭 → 记录新 md5**。

- 每份文件先用 `reset` 从 `poc/.pristine/` 复位，保证 before 是已知字节。
- `save()` 走的是 POC 自己的写盘接口（`PUT /poc-fs/write`），等价于产品的「保存」动作。
- **三层交叉验证**：① 浏览器侧写请求日志（dev 中间件记 `{时间, 文件, 来源, 字节, md5}`）；② Node 侧 `fs.watch` 目录监视；③ 磁盘 md5 + mtime。
- 所有字节数均为 **LF 行尾**下的值（`poc/.pristine/` 是基准副本）。⚠️ 本机 `core.autocrlf=true`，`git checkout` 出来的工作区副本是 CRLF，与基准不符——复现时以 `.pristine/` 为准。

脚本：`.workbuddy/tmp/donote/poc-untouched.cjs`（用例 1）、`poc-round1.cjs`（用例 1 变体 + 用例 2）、`poc-smoke.cjs`（冒烟）。

### 5.4 改写清单（按来源归类）

| 改写 | Milkdown | Vditor `ir`/`wysiwyg` | 性质 |
|---|---|---|---|
| 无序列表 `-` → `*` | 是 | 否 | 序列化器默认标记 |
| 分割线 `---` → `***` | 是 | 否 | 序列化器默认标记 |
| 公式内转义 `\,` → `,` | 是（`\,` 被吃掉） | 否 | **内容损失**（LaTeX 语义被改） |
| 任务列表 `[x]` → `[X]  ` | 否 | 是（大写 + 两个空格） | 序列化器默认写法 |
| 表格分隔行与列宽重排 | 是（`\| -- \|`） | 是（`\| ---- \|`） | 列宽对齐 |
| 表格前补空行 | 否 | 是 | 空行规范化 |
| 行尾空格清除 | 是 | 是 | 空行/空白规范化 |
| 空行被吞或补回 | 是 | 是 | 空行规范化 |
| 引用嵌套重排（`> > > >` ↔ `>>>>`） | 是 | 是 | 两种合法风格互转 |
| 文件末尾空白行变 `    ` | 否 | 是 | 空白规范化 |

**判断**：其中「表格列宽对齐」「行尾空格清除」「引用风格互转」「空行规范化」属于可接受的风格迁移；但 **`-` → `*`、`---` → `***`、`[x]` → `[X]` 只是写法变化，而 `\,` → `,` 是内容损失**。详见 §5.6 的分级。

### 5.5 规范化到底会带来什么后果

字节差异本身不能说明严重程度。做了两项换算：

**（1）渲染结果逐行比对**：用 markdown-it（标准 GFM）分别渲染原文与保存后的文件，把 HTML 每行一个标签摊平后做 LCS 比对。

| 文件 | Milkdown | Vditor `ir` | Vditor `wysiwyg` | Vditor `sv` |
|---|---|---|---|---|
| 基础语法 | 0 | 6 ※ | 2 ※ | 0 |
| 外部修改-符号变更 | 0 | 6 ※ | 2 ※ | 0 |
| 外部修改-空行调整 | 0 | 6 ※ | 2 ※ | 0 |
| 外部修改-行尾空格 | 0 | 6 ※ | 2 ※ | 0 |
| 外部修改-编辑器规范 | 0 | 6 ※ | 2 ※ | 0 |
| 极端 | 0 | **14** | **2** | 0 |

（数字 = 渲染 HTML 的差异行数，0 = 渲染结果完全一致）

※ 标记的差异**全部**来自 `<li>[x] …</li>` → `<li>[X] …</li>`。这是 markdown-it 默认不带任务清单插件才显示出来的差别——接上 GFM 任务清单渲染后两边完全一致。**真正的渲染差异只出现在 `极端.md`：**

- **Vditor `ir`（14 行）**：表格里 `` `\|x\|` `` 与 `` `a \| b` `` 的转义被还原，表格从该行起被打散，两个行内代码消失（`<code>` 2 → 0）；另外硬换行丢失。
- **Vditor `wysiwyg`（2 行）**：硬换行丢失。表格保住了。

**（2）幂等性**：把「已保存过一次」的文件再喂回同一编辑器，反复保存 3 轮。

| 模式 | 基础语法.md | 极端.md |
|---|---|---|
| Milkdown | 第 2 轮起稳定 | 第 2 轮起稳定 |
| Vditor `ir` | 第 2 轮起稳定 | **第 3 轮才稳定** |
| Vditor `wysiwyg` | 第 2 轮起稳定 | 第 2 轮起稳定 |
| Vditor `sv` | 第 2 轮起稳定（且从未变过） | 第 2 轮起稳定 |

结论：**规范化基本是「一次性」的，不会持续漂移**——代价集中在第一次保存。唯一例外是 `极端.md` 上的 Vditor `ir`，它要两次才收敛，而且中间那一轮是**恶化**：

```diff
  原文          | 绝对值 | `\|x\|` | 竖线用反斜杠转义 |
  第 1 次保存后  | 绝对值 | `|x|`   | 竖线用反斜杠转义 |   ← 单元格被拆成三段
  第 2 次保存后  | 绝对值 | `        | x                |   ← 内容彻底散架
  第 3 次保存后  （不再变化）
```

### 5.6 严重程度分级

| 级别 | 现象 | Milkdown | Vditor `ir` | Vditor `wysiwyg` | Vditor `sv` |
|---|---|---|---|---|---|
| **P0** 内容被改错 | 表格单元格内的转义管道符 `` `\|x\|` `` → `` `\|x\|` `` 被还原，整表打散，且连续两轮恶化 | — | **中招** | — | — |
| **P0** 内容被改错 | 公式内 LaTeX 间距指令 `\,` 变成字面逗号 `,`（`x^2 \, dx` → `x^2 , dx`） | **中招** | — | — | — |
| **P1** 语义丢失 | 行尾两个空格构成的硬换行被删（段落内换行合并） | 保住（改写成 `\`） | **中招** | **中招** | — |
| **P2** 纯写法 | 无序列表 `-` → `*`、分割线 `---` → `***`、表格列宽重排、空行压缩 | 中招 | — | — | — |
| **P2** 纯写法 | 任务项 `[x]` → `[X]  `、表格列宽重排、表格前补空行、末尾空白行变 4 空格、空行压缩、多级引用 `> > >` → `>>>` | — | 中招 | 中招 | — |

**读法**：

- 两个编辑器的弱点**互补**——Milkdown 只在数学公式上出错，表格、代码、列表的改写都渲染无关；Vditor 反过来，公式完全不动，但表格和硬换行会出事。
- **P2 那几项可以接受**：只是把用户的写法统一成编辑器的默认风格，渲染出来一个字都不差。唯一的不适是「下次用别的工具打开，看到的不再是自己写的格式」。
- **P0 那两项不能接受**：一个是渲染出错误表格（内容散架），一个是渲染出错误公式（凭空多一个逗号）。
- **幂等性是一条重要的缓解事实**：不是每保存一次就改一次，是首次保存规范化一次就固定。

**按「谁的笔记里有什么」来判断风险**：

| 用户的笔记内容 | Milkdown 风险 | Vditor 风险 |
|---|---|---|
| 只要标题、段落、列表、引用 | 无（仅写法统一） | 无（仅写法统一） |
| 含任务清单 `- [x]` | 无 | 无（仅写法统一） |
| 含 Markdown 表格 | 无 | **高**（单元格里有代码或 `\|` 时内容散架） |
| 含数学公式 | **中**（`\,` 等间距指令被吃） | 无 |
| 依赖行尾两空格做硬换行 | 无 | **中**（硬换行丢失） |

## 七、已知坑（供后续参考）

1. **Vditor 的 `cdn` 路径规则不统一**：取 i18n 时会在 `cdn` 后面再拼一层 `/dist/`，其它资源不拼。本地托管时两边都要认，否则 `lute.min.js` 404 → 白屏（`Cannot read properties of undefined (reading 'currentMode')`）。
2. **Vditor 默认从 unpkg 懒加载** `lute.min.js` / `mermaid` / `highlight`，单文件实测耗时约 14s。必须自托管或预加载。
3. **Milkdown 的无序列表标记不可配**：`@milkdown/preset-commonmark` 的 `bulletListSchema.toMarkdown.runner` 里硬编码 `openNode('list', void 0, { ordered: false, spread })`，没有 bullet 标记选项（`bulletListAttr` 只影响 `toDOM`，不影响序列化）。
4. **`@milkdown/vue` 不随 `@milkdown/kit` 一起安装**，需要单独 `pnpm add @milkdown/vue`。
