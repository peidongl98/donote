# poc/fixtures —— 编辑器保真回归用的测试文档

这些 .md 不是产品的一部分，是「编辑器会不会悄悄改写用户文件」的回归样本。
批次 1c 挑编辑器时写的，之后每次动编辑器都该拿它们跑一遍。

## 每份文件测什么

| 文件 | 覆盖 |
|---|---|
| `基础语法.md` | 六级标题、粗/斜/删、行内代码、围栏代码块、有序/无序/嵌套五层列表、任务清单、嵌套引用、表格（含单元格内管道符）、引用式链接、图片、分割线、行内与块级公式、脚注、mermaid |
| `外部修改-符号变更.md` | 由基础语法改：无序列表 `-` → `*` |
| `外部修改-空行调整.md` | 由基础语法改：删掉 H1 后的空行 |
| `外部修改-行尾空格.md` | 由基础语法改：段落与标题行尾加两个空格 |
| `外部修改-编辑器规范.md` | VS Code + Prettier 3（`--parser markdown`）的真实产物 |
| `极端.md` | 代码块内含 ` ``` ` 与 ` `` `、表格单元格内含 `\|`、五层嵌套列表、超 1000 字符单行、连续 10 个空行、四级引用 |
| `公式.md` | 7 种 LaTeX 间距写法（`\,` `\:` `\;` `\!` `\ ` `\quad` `\\`），含多行 aligned 环境 |
| `美元边界.md` | 普通文本/行内代码/代码块/表格里的 `$` 不能被当成公式 |
| `空文件.md` | 零字节边界 |

## 怎么用

判据是**逐字节对比**，不是「看起来差不多」：

1. 记下原文件的 md5 与字节数；
2. 用编辑器打开、**什么都不改**、触发一次保存、关闭；
3. 对比新旧 md5 —— 完全一致才算通过。

⚠️ 这些文件是**按字节**测量的基准，`poc/.gitattributes` 里显式关掉了换行转换。
Windows 上 `core.autocrlf=true` 会把 LF 换成 CRLF，字节数当场就变，比出来的结果全是假的。

⚠️ 判定「能不能接受」时，光看字节数不够 —— 还要把原文和保存后的文件各自用标准
GFM 渲染一遍，比对渲染结果。有些改动（表格列宽、`-` 换 `*`）只是写法变了，渲染不变；
有些（公式里的 `\,` 被吃、表格里的 `\|` 被还原）是真错。两类要分开看。
